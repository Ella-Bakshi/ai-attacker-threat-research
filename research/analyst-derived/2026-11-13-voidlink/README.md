# VoidLink: independently derived static evidence, 13 November 2026

Two exact SHA256s listed by [Check Point on 13 January 2026](https://research.checkpoint.com/2026/voidlink-the-cloud-native-malware-framework/) were acquired from the documented public MalwareBazaar 30 October daily ZIP. Only exact member ranges were fetched. Each member passed size, CRC32 and SHA256 checks; the acquisition receipt preserves requested and returned ranges. This is independent analysis of previously published artifacts, not first-party victim telemetry or a claim of globally novel indicators.

For SHA256 `4c4201cc1278da615bacf48deef461bf26c343f8cbb2d8596788b41829a39f3f` (1,254,808 bytes), bounded native analysis completed the critical configuration function at `0x10aa478`. The literal `8.149.128.10` is at file offset 278961 / VA `0x10441b1`. Two direct native references, the `c2_host` lookup, configuration-object stores, and a C2-host log-format context establish a compiled default C2-host role. Native port initialization uses 443 (`0x1bb`) and looks up `c2_port`, falling back to `port`; configuration can override both host and port. The default pair is therefore **`8.149.128.10:443`**. No connection was made. Port 443 alone does not prove protocol.

[Sysdig reported 8.149.128.10:8080 on 16 January 2026](https://www.sysdig.com/blog/voidlink-threat-analysis-sysdig-discovers-c2-compiled-kernel-rootkits). Retain that publisher observation separately: the acquired 4c4201 bytes support default 443 and do not independently establish 8080. The IP is externally known; our contribution is an exact-byte/native corroboration and a variant-specific default-port derivation. Neither endpoint establishes present-day control, activity or victim infection.

SHA256 `6dcfe9f66d3aef1efd7007c588a59f69e5cd61b7a8eca1fb89a84b8ccef13a2b` exactly matches the public member at 1,048,576 bytes but is structurally truncated: its declared first load segment and section table exceed EOF, and its entrypoint/code segment is beyond available bytes. Its IP literal at file offset 1027060 is literal-presence corroboration only. No C2-port or native-flow claim is made for that variant.
