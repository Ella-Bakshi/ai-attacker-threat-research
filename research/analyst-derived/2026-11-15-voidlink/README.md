# VoidLink: a separately acquired configuration variant

Reviewed **15 November 2026**. We acquired the exact artifact SHA256 `6850788b9c76042e0e29a318f65fceb574083ed3ec39a34bc64a1292f4586b41`, listed in [Check Point's 13 January analysis](https://research.checkpoint.com/2026/voidlink-the-cloud-native-malware-framework/). Acquisition used only its exact member ranges from the public MalwareBazaar 30 October archive. The full 1,197,200-byte member passed length, CRC32 and SHA256 checks. Its declared ELF load ranges and section table are within the acquired file.

Our offline disassembly establishes the compiled fallback **`8.149.128.10:8080`** on the selected configuration branch. The host literal is at file offset **257776**, virtual address **`0x103eef0`**. Instruction **`0x10b99c2`** loads that host pointer; **`0x10b99c8`** initializes port 8080 (`0x1f90`). The configuration path looks up `port` and `c2_host`, conditionally replaces the defaults, then stores the host pointer/length and port into the same configuration object at **`0x10b9aa3`**, **`0x10b9aaa`** and **`0x10b9ab4`**. [Selected native evidence](native-config-evidence.json) preserves exact bytes, offsets, addresses and limits.

This independently corroborates the externally known IP and 8080 endpoint. It does not add a new unique IP or establish live operation. The previously examined `4c4201…` artifact has a distinct compiled default of 443; neither default should be copied to the other variant, and runtime configuration can override both. Port 8080 alone does not establish a protocol.

The five observations are three hash identities for **one artifact**, one IP corroboration and one endpoint corroboration. Only the three file-hash values are new to the repository master at this review. [Artifact identity](artifact-identity.json) bridges the algorithms; [acquisition provenance](acquisition.json) separates archive retrieval from analyst derivation. Publisher attribution and AI-development assessment remain external evidence; the local bytes do not independently prove AI authorship.

The native method was bounded Capstone disassembly with ELF address mapping. The direct-CALL target and prologue support `0x10b9972` as a function-entry candidate; complete function recovery and whole-program decompilation were not performed. High confidence concerns exact bytes and the selected fallback/override path. Operational confidence is medium because execution, connections, actor control and victims are unobserved. No India association or global first-discovery claim is made.

DNS defaults, cloud metadata addresses, loopback and version-like dotted strings were withheld without a controller-role proof. No malware execution, controller launch, target HTTP/TLS/DNS request, scan, paid-provider call or sample submission occurred. Raw binaries, decompiler projects, authentication secrets and control instructions are excluded from this evidence view.
