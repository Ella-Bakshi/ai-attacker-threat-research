# Indicator reliability and appropriate use

An observable is useful through its source, role, time and context. An exact hash, an indexed console and a reported C2 address answer different questions. This catalog and map are research inventories; their full contents are not an automatic block list.

| Evidence class | Supported interpretation | Limit |
|---|---|---|
| Source-reported incident/campaign IOC | The publisher associates the value with the stated historical role | Preserve role, dates, corrections and attribution scope |
| Our artifact extraction | An identity/configuration/event was independently reproduced in an exact artifact | Configured intent or an attempted exchange is not successful operation, victim evidence or current ownership |
| Software fingerprint/detection hypothesis | A source/asset/pattern supports software or lineage research | Legitimate use, common components and untested detection efficacy remain separate |
| Passive deployment lead | A provider historically indexed a value/service or marker | Installation is not hostile use or present liveness |
| Supporting/shared service | The source describes a supporting component or context | Shared hosting, legitimate services and API resellers are not dedicated C2 by association |
| Unverified/conflicting finding | A precise identity, role or relationship question remains open | Keep separate until the missing proof is obtained |

Our artifact finding means a reproducible derivation with an exact hash and byte/code/event locator. It does not imply first-party sensor collection or global first discovery. Multiple hashes for one file are multiple identities, not multiple samples. Five source hash literals currently retain algorithm qualifications; freshly recomputed supporting-file bridges are distinguished from provider metadata.

## Confidence has a scope

High confidence in a literal, hash or software match does not establish maliciousness. The map's documented evidence-strength labels are ordinal, not probabilities. Hosting enrichment never increases them. Read the written basis and competing evidence. Missing source-review metadata defaults to unresolved. An unresolved record cannot independently earn a C2 flag or more than 10; nonindicative context stays0. Other supported records for the same IP retain their own roles and scores.

IP, port, hostname/SNI, sample variant and observation time must stay connected to their evidence. A certificate at another port, neighboring address, ASN or hosting country does not establish that relationship. Provider indexing, sample submission, certificate validity, acquisition, enrichment and victim activity are separate clocks; blank dates remain unknown.

The [FBI compilation](https://www.ic3.gov/CSA/2026/261113.pdf) repeats the table variant without resolving that discrepancy. Repetition is not independent endpoint evidence.

## Operational use

Use source-reported malicious indicators with historical roles, freshness and local context. Review reassigned/shared addresses and mutable image tags before enforcement. Hash matching requires the exact algorithm and artifact identity. Software fingerprints and passive leads require separate evidence before classification as malicious infrastructure. Finite reference matches provide no implied production false-positive estimate.

The map Source review filter and the separate unresolved CSV expose these distinctions. An IP can have mixed source memberships; one supported observation does not verify every other claim attached to that address. Read the original source, record scope and limitations before acting.
